# 模块边界

#architecture #code

## 解决方案结构

```text
Ssvep.Speller.sln
├─ src/
│  ├─ Ssvep.Speller.App/      WPF 可执行应用
│  └─ Ssvep.Speller.Core/     可测试核心逻辑
└─ tests/
   └─ Ssvep.Speller.Tests/    xUnit 测试
```

## App 不应该做什么

App 层可以组合流程，但不应该把核心算法写死在 UI 控件里。当前已经抽到 Core 的逻辑包括：

- 刺激目标和动作。
- CCA/FBCCA。
- 决策引擎。
- 反馈路由。
- 数据采集 trial 调度。
- EEG 环形缓冲和通道投影。
- 阻抗就绪门控。
- 日志写入。

## Core 不应该做什么

Core 层不依赖 WPF 控件，不直接操作窗口、按钮、TextBox、Brush、Dispatcher。这样测试项目可以直接引用 Core 并快速验证。

## 当前耦合点

`MainWindow.xaml.cs` 仍然是最大耦合点，它直接持有：

- `ISsvepClassifier`
- `HybridDecisionEngine`
- `TextComposer`
- `EegRingBuffer`
- `SynchroniBridgeEegStream`
- `SessionLogWriter`
- `DataCollectionLogWriter`
- `DataCollectionController`
- `ChannelMontage`

这对 V1 原型可接受，但如果后续继续增加实验范式，应考虑把以下服务拆出：

- `TypingSessionController`
- `CollectionSessionController`
- `DeviceConnectionController`
- `DiagnosticsViewModel`
- `StimulusSettingsViewModel`

## 公共接口

| 接口/类型 | 作用 |
| --- | --- |
| `IEegStream` | 统一模拟 EEG 和真实设备 EEG |
| `ISsvepClassifier` | 统一 CCA 和 FBCCA |
| `StimulusTarget` | 目标 ID、显示文字、频率、相位、动作 |
| `ClassificationResult` | 分类分数和 best/second/margin |
| `DecisionResult` | 最终提交目标和反馈来源 |
| `DataCollectionTrial` | 单次采集 trial 的 cue 和 feedback 计划 |
