# 信号窗口与缓冲

#signal #algorithm

## 为什么需要环形缓冲

真实设备样本是逐点到达的，而 CCA/FBCCA 需要一个二维窗口矩阵：

```text
window[sampleCount, channelCount]
```

所以 SDK 读取任务持续把样本写入 `EegRingBuffer`，分类计时器每 250ms 取一次最新 625 个样本。

## 当前窗口

| 项 | 值 |
| --- | ---: |
| 采样率 | `250 Hz` |
| 窗口样本 | `625` |
| 窗口时长 | `2.5 s` |
| 分类步长 | `0.25 s` |
| 通道数 | `8` |

## TryReadLatestWindow

当缓冲样本不足 625 时返回 `false`，UI 会显示：

```text
正在等待足够的 Synchroni 脑电样本...
```

这是正常启动状态，不一定是设备错误。若样本数持续增加但 buffer 一直不到 625，检查通道筛选是否频繁重置；若样本数不增加，检查设备连接。

## 通道筛选对缓冲的影响

更改有效 8 通道选择后：

1. 新建 `ChannelMontage`。
2. 清空 `sdkRingBuffer`。
3. 状态提示重新积累缓冲。
4. 至少等待 2.5 秒新样本后才能分类。

## 合成信号

模拟模式不走 ring buffer。`RecognitionTimer_Tick` 会按当前 focus 目标直接生成 625 x 8 的合成窗口，再交给 FBCCA。
