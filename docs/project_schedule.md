# SSVEP Speller Project Schedule

更新日期：2026-06-07

## 时间投入假设

| 时间 | 可投入时长 | 建议工作类型 |
| --- | ---: | --- |
| 周一 | 1 小时 | 计划、复盘、轻量实现 |
| 周二 | 1 小时 | 小范围代码改动或实验准备 |
| 周三 | 1 小时 | 测试、日志分析、参数整理 |
| 周四 | 1 小时 | 构建验证、文档、周末实验准备 |
| 周五 | 0 小时 | 休息，不安排关键任务 |
| 周六 | 4 小时 | 真实设备实验、较大功能实现 |
| 周日 | 4 小时 | 长时间验证、问题修复、总结 |

每周标准容量为 12 小时。周中只安排能在 1 小时内闭环的小任务，周末安排需要设备、连续运行或较长上下文的任务。

## 每周复盘模板

| 项目 | 内容 |
| --- | --- |
| 本周完成 | 列出完成的任务 ID、代码改动、实验记录 |
| 本周数据 | 样本稳定性、丢包、阻抗范围、FPS、准确率、延迟 |
| 阻塞问题 | 明确复现条件、截图或日志路径 |
| 下周优先级 | 最多 3 个 P0/P1 任务 |
| 是否调整排期 | 若设备、SDK 或识别结果偏离预期，更新下一周计划 |

## 排期调整规则

| 情况 | 调整方式 |
| --- | --- |
| 设备连接或采样不稳定 | 暂停算法优化，优先修连接和日志 |
| 阻抗长期无法低于阈值 | 先放宽阈值做实验，同时记录噪声和识别影响 |
| 周末无法实测设备 | 周末改做代码和文档，设备实验顺延到下一周 |
| 识别准确率明显低 | 优先做通道选择、刺激参数、阈值和诊断，不急于做复杂 UI |
| 页面或刺激布局影响视觉效果 | 优先保证刺激区域和刷新率，诊断信息移回设置页 |
