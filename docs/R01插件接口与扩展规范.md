# R01 脑控外设插件接口与扩展规范

版本 0.3 · 2026-09-13 · 架构评审稿，尚未实现

本规范落实用户提出的“先做脑控小车，后续可添加机械手脑控软件”。第二套软件采用独立桌面宿主和外设插件；小车作为首个正式插件，机械手作为后续独立插件。第一套通用 SSVEP 软件是另一款产品，两者共用采集、刺激、识别和会话基础库。

## 1 扩展边界

| 模块 | 公共宿主负责 | 插件负责 |
| --- | --- | --- |
| 脑电与算法 | SDK 连接、内部采样与窗口配置、CCA/FBCCA、单次结果校验与拒识 | 不直接访问脑电帽、不重复实现识别 |
| 刺激界面 | 目标渲染、帧时序、提示、开始暂停停止、静态预览 | 提供六个固定目标的内容与动作绑定，不接管编码或逐帧渲染 |
| 设备 | 设备绑定、连接状态汇总、独占控制权限 | 搜索、连接、协议转换、设备状态解释 |
| 动作 | 映射校验、权限、有效期、串行派发、停止优先 | 动作参数、设备能力检查、协议发送与应答 |
| 界面 | 从配置和遥测描述生成设置表单、状态区、动作映射页 | 提供声明式字段、单位、范围、枚举和显示顺序 |
| 停止 | 撤销运行代次、清空普通队列、独立停止请求、故障展示 | 将停止翻译为设备命令；设备侧看门狗由硬件或固件落实 |
| 记录 | 样本、刺激、识别、命令、应答、版本与异常 | 上报协议事件及真实可观测状态 |

**运行参数不对用户开放。** 频率/编码、相位、目标数量、采样率、窗口时长由宿主的内部运行配置管理。插件只引用兼容的配置 ID，并提供固定六个目标的内容、动作绑定及设备参数；插件设置描述、内容包和普通应用 API 不允许覆盖受限字段。宿主加载时拒绝不匹配的数量、配置引用或受限字段，不通过插件或“高级设置”重新开放这些选项。

**识别采用单次结果提交。** 一个通过质量与时效检查的分类结果即可进入派发，不进行连续三次确认。命令 ID 去重、停止仲裁及设备应答保留；设备确认属于命令执行反馈，与识别重复确认是不同机制。

首版插件不注入任意 WPF 视图。常见连接设置、按钮、数值、枚举、状态与简单空间反馈由宿主统一呈现。未来机械手若需要三维轨迹规划或复杂示教界面，作为可选视图扩展另行设计，不计入首版插件接口承诺。

**机械手软件的交付形式：**通常是“脑控外设宿主 + 机械手插件 + 专属默认方案和桌面入口”。如果要求与小车完全独立安装，可生成两个应用配置包并共享同版宿主组件；不复制算法源代码。独立进程运行时也必须遵守设备独占控制规则。

## 2 插件运行与分发

采用本机子进程插件，宿主通过专用本机命名管道交换有长度前缀的 UTF-8 JSON 消息。每个激活插件只有一个工作进程；标准输出和错误输出只作为诊断日志，不与协议混用。C#、Python、C++ 均可实现同一协议，无需把外部代码装载进 UI 进程。

首版同时只激活一个外设插件、绑定一台外设。暂停期间同样不允许切换或升级。切换流程为：结束实验 → 确认设备停止或显式处理停止未知故障 → 断开设备 → 退出旧插件 → 激活新插件。插件升级失败回退到上一已验证版本，不迁移到一半继续执行动作。

工作进程隔离用于限制崩溃影响，**不是安全沙箱**。交付插件来自明确的本地安装包；用户选择安装后先检查清单、文件摘要、路径和兼容性，再加载。首版不做在线市场、自动下载或运行中热更新。

## 3 包结构和版本

```text
vehicle-plugin-1.0.0/
  manifest.json             身份、接口版本、入口及依赖
  actions.schema.json      动作、参数、限值、停止语义
  settings.schema.json     连接与运行配置表单
  telemetry.schema.json    可显示状态、单位、枚举
  presets/car-six.json      内部配置引用、六目标内容、动作映射
  assets/                  目标图像等静态素材
  bin/                     插件程序和固定版本依赖
  docs/                    接入步骤、协议说明、故障处理
  tests/                   模拟端及契约测试材料
```

清单示例为设计值，不代表当前已存在安装包：

```json
{
  "id": "ssvep.device.vehicle",
  "name": "脑控小车",
  "version": "1.0.0",
  "contractVersion": "1.0",
  "hostVersionRange": ">=1.0.0 <2.0.0",
  "entry": "bin/Vehicle.Plugin.exe",
  "transport": "local-named-pipe-json",
  "deviceFamilies": ["vehicle"],
  "schemas": {
    "actions": "actions.schema.json",
    "settings": "settings.schema.json",
    "telemetry": "telemetry.schema.json"
  },
  "defaultPreset": "presets/car-six.json",
  "supportsSimulation": true
}
```

所有入口和资源路径都相对插件目录，不允许逃逸路径。清单、配置与动作描述在加载时共同校验；相同 ID 的重复包不能静默覆盖。接口主版本不兼容时阻止激活；次版本只能增加可选能力，未知必需能力应报错。依赖版本和每个实际加载文件的摘要进入会话记录。

配置以 `schemaVersion` 迁移，保留原配置备份。升级后若动作删除、改名、参数单位变化或限值收紧，旧方案必须重新校验，不能只凭名称相似自动映射。

## 4 协议与生命周期

| 消息 | 目的 | 返回或约束 |
| --- | --- | --- |
| `Hello` / `Describe` | 握手与能力协商 | 身份、接口版本、动作、配置和遥测描述；加载时与清单一致 |
| `Discover` | 搜索可连接设备 | 稳定设备 ID、名称、连接方式；不能自动绑定陌生设备 |
| `Connect` | 连接明确设备 | 返回实际型号、固件、能力、状态、是否需要参考点或使能 |
| `Prepare` | 验证运行配置 | 参数、单位、运动范围、停止方式、看门狗能力和默认方案可用性 |
| `Enable` | 获取新的控制许可 | 仅在设备与脑电就绪且用户开始时；返回本次设备控制代次 |
| `Execute` | 执行动作 | 关联命令 ID、会话 ID、运行代次和设备控制代次；有截止时间 |
| `Stop` | 优先停止所有运动 | 与普通队列独立接收；重复调用应幂等；报告停止确认或未知 |
| `Status` / `Telemetry` | 查询或推送设备状态 | 已接收、执行中、已完成、失败、未知分别表达 |
| `Health` | 检查插件存活 | 带序号和时间；插件存活不等于外设连接正常 |
| `Disconnect` / `Shutdown` | 停止后释放资源 | 释放设备和管道；进程退出后宿主回收资源 |

状态建议：`Discovered → Validated → Loaded → Connected → Ready → Enabled`。任何运行状态可进入 `Faulted`；从故障恢复只能回到连接或检查流程，不自动恢复到 `Enabled`。实际设备没有使能能力时，`Enabled` 仍是宿主控制许可，不得声称硬件已使能。

单条消息采用 `messageType`、`requestId`、`protocolVersion`、`pluginInstanceId`、`payload`。请求与应答关联，明确最大消息大小和有界队列；数值必须有限，缺失必填字段、超限值及未知动作拒绝执行。建议首版单条 JSON 上限 256 KiB，素材通过包内路径引用。

### 4.1 动作模型

动作以稳定 ID 标识，含名称、参数类型、单位、上下限、是否导致运动、是否可重试、应答级别和停止语义。动作类别至少覆盖即时动作、带限值的点动和持续运动。宿主不把“左转”统一假定成角度、时长或速度：具体参数由插件声明。

| 层级 | 小车示例 | 机械手示例 |
| --- | --- | --- |
| 设备动作 | `vehicle.forward`、`vehicle.backward`、`vehicle.turnLeft`、`vehicle.turnRight`、`device.stop` | `gripper.open`、`gripper.close`、`arm.jogUp`、`arm.jogDown`、`device.stop` |
| 宿主动作 | `session.pause` | `session.pause` |
| 限值 | 速度、持续时长、转向方式，按实际硬件协议 | 力或电流、位移、坐标系、软硬限位，按实际硬件协议 |

六目标小车预设建议为前进、后退、左转、右转、停止、暂停脑控。停止目标只停止设备，识别会话可继续；暂停脑控同时停止设备并暂停识别，需手动恢复。硬件不支持的动作不出现在可绑定列表中。机械手参考预设必须根据实际夹爪或机械臂能力调整，普通夹爪不默认具备上下移动或回零能力。

### 4.2 命令结构与应答

```json
{
  "commandId": "uuid",
  "sessionId": "uuid",
  "runEpoch": 4,
  "deviceEpoch": 2,
  "deviceId": "bound-device-id",
  "actionId": "vehicle.forward",
  "parameters": {"durationMs": 300},
  "deadlineHostMonoMs": 912345,
  "inputMode": "live"
}
```

示例的 300 ms 仅用于说明带时长的动作，不是硬件默认参数。超时以宿主单调时钟判断；插件启动时协商与宿主时钟的偏移和误差，不能直接比较不同进程未经约定的相对时钟。宿主发送前、插件执行前分别校验有效期、代次与设备身份。

应答分为 `Rejected`、`Accepted`、`Executing`、`Completed`、`Failed`、`Unknown`。没有设备确认时仅能记录 `Sent` 或 `Unknown`，不能伪造 `Completed`。命令 ID 去重只避免当前插件重复请求，不能自动证明固件已执行恰好一次；无设备去重且执行结果未知的运动命令不自动重试。

## 5 停止、看门狗和故障

宿主输出门控统一检查：真实输入、正确会话及运行代次、脑电质量、已绑定设备、插件健康、设备控制许可、参数限值。模拟输入或原型点击只能进入模拟端，不进入实物输出。

停止立即使普通执行许可失效，撤销待执行指令，然后走独立停止通道。插件的协议读取与普通设备执行不能是同一条阻塞任务，否则无法及时处理停止。停止和普通动作发送须有最终仲裁，已撤销的动作不能在停止发送之后才开始下发。

运动设备需要设备侧看门狗，或等效的有限时长动作协议。普通插件心跳不能自动延长运动有效期：只有当前有效控制许可下的消息才可续期；停止后停止续期。杀死插件进程只能终止软件派发，不能证明物理设备已经停止。

以下均为待实测的建议配置：插件健康间隔 200 ms，连续 3 次丢失判故障；脑电数据过期阈值 500 ms；设备运动看门狗最后有效控制消息后不超过 1 秒停止。实际阈值须按设备链路、控制模式和实验环境核定，记录阈值与测量结果。

| 触发 | 宿主动作 | 界面与恢复 |
| --- | --- | --- |
| 插件崩溃、无响应 | 清候选和队列、撤销控制许可、请求停止；必要时退出进程 | 显示设备停止确认或未知；处理后重新连接 |
| 外设掉线、应答超时 | 停止普通命令，记录未知结果，不自动补发 | 恢复连接后重新使能，不重放运动 |
| 脑电失效、记录写入失败 | 暂停或终止会话，停止设备，保留失败原因 | 新会话或显式重新检查，不能静默继续 |
| 能力不匹配、旧方案失效 | 拒绝进入 Ready | 标明具体目标、动作和参数错误 |
| 两应用争用脑电帽 | 第二个申请者不得启动新的采集连接 | 显示设备正在使用及应用名称，主动释放后再接入 |

## 6 后续开发机械手的步骤

1. 选定硬件和协议，核实连接、动作、应答、限值与停止能力。
2. 从插件模板创建新 ID，填写版本、入口、设备设置、动作、遥测及六目标内容/映射；引用宿主内置运行配置。
3. 实现连接、准备、执行、停止、状态和断线处理；提供机械手模拟端。
4. 使用独立插件测试工具验证协议、非法参数、超时、去重、停止竞争和崩溃。
5. 安装到未修改的宿主上，验证自动生成的设置页和目标映射；运行小车回归。
6. 完成机械手实物联调、真实脑控和教学材料，再将该插件标记为正式可交付。

首版交付 C# 小车参考插件；为满足 Python/C++ 二次开发目标，交付两种语言的最小协议客户端或外设模拟插件、编译环境说明及契约测试用例。它们是语言接入示例，不单独计作新的外部硬件种类。

## 7 插件验收

| 编号 | 检查 | 通过证据 |
| --- | --- | --- |
| P01 | 小车作为独立插件被发现、加载、连接和控制 | 插件包、版本记录、实机动作及反馈 |
| P02 | 不修改宿主源码安装机械手模拟插件 | 自动生成配置、动作及反馈；源码或构建差异记录。此项仅证明扩展架构 |
| P03 | 不兼容接口、缺依赖、损坏文件、越界路径或重复 ID | 阻止加载，错误明确，宿主仍可用 |
| P04 | 运行与暂停期间切换、卸载或升级 | 操作不可执行，当前绑定不被替换 |
| P05 | 插件崩溃、设备掉线、脑电中断、停止与命令竞争 | 无新的普通动作；停止确认与未知正确区分；设备侧停止单独实测 |
| P06 | 延迟回包、过期命令、重复 ID、错误设备代次 | 无重复运动或跨设备误派发；完整审计记录 |
| P07 | 插件升级改变动作与参数 | 原方案重新校验，失败时禁止开始；可回退旧包和配置 |
| P08 | Python/C++ 示例在另一台电脑运行 | 依赖及构建说明、契约测试和连接记录 |
| P10 | 参数封闭与单次结果 | 一个有效分类结果即可派发；配置表单、内容包或插件不能开放/覆盖编码、相位、数量、采样率及窗口时长 |
| P09 | 第二类真实硬件案例（机械手确定后） | 独立实物、插件、实验指导和真实脑控记录；不能用模拟插件替代 |

P01–P08、P10 属于插件架构与开发包验收；P09 属于整套采购的第二类外设案例验收。当前只完成设计与原型，不把规划中的插件包或测试工具列为已实现能力。
